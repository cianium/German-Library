# German Library V7.3.0 — گزارش توسعه و تحویل

## دامنه نسخه

**مرجع:** سورس V7.2.0 با تفکیک Book Package و Independent Library. فایل‌های backend/schema و Seed دست‌نخورده باقی مانده‌اند. معماری Vanilla JS، RLS، signed URL، Auth و Cloud Sync قبلی حفظ شده‌اند.

### رابط کاربری
- تم زغالی پیش‌فرض با طلایی مات و Light Mode اختیاری (محلی در مرورگر).
- خانه ساده‌تر؛ شش کارت فشرده A1–C2؛ منابع مستقل همچنان جدا از کتاب‌ها هستند.
- Navigation موبایل چهار مقصد با آیکون و `aria-current`، رعایت Safe Area.
- Header هماهنگ و دکمه تغییر تم؛ Footer مشترک دارای امضا و لینک‌های **شناخته‌شده** GitHub و وب‌سایت شخصی. دیگر شبکه‌های اجتماعی بدون URL تأییدشده اضافه نشده‌اند.
- فیلتر سریع مهارت‌ها در منابع مستقل، با نمایش مهارت‌هایی که واقعاً در Catalog وجود دارند.

### Content Studio موبایل
- تب‌های Overview / Books & Files / Independent Library / Tools؛ نوار ناوبری پایین جداگانه.
- Quick Actions برای ایجاد کتاب، منبع مستقل، مشاهده سلامت انتشار و ابزارهای Sync.
- هر Book Package امکان افزودن فایل مرتبط و نمایش/ویرایش فایل‌های داخل خود بسته را دارد.
- منابع مستقل در فهرست مدیریتی جدا هستند؛ امکان انتخاب چند مورد و تبدیل آنها به Draft یا Archive با تأیید.
- بررسی آمادگی انتشار **ساختاری**: اعتبارسنجی Catalog، URL/Storage Path، موارد وابسته به کتاب بدون package و وضعیت دستی بررسی لینک؛ این قابلیت درخواست HTTP یا بررسی صحت URL خارجی انجام نمی‌دهد.
- نمایش نقش مدیر/ویرایشگر؛ تغییر نقش کاربران برای جلوگیری از تضعیف امنیت در این نسخه پیاده نشده است.

### نحوه اجرای موبایل / Termux
```sh
cd ~/storage/shared/Download
unzip german-library-v7.3.0-source.zip -d german-library-v7.3
cd german-library-v7.3
python3 -m http.server 8080
```
سپس آدرس `http://127.0.0.1:8080/index.html` را در همان دستگاه باز کن. برای نمایش پنل مدیریت در حالت Demo محلی: `http://127.0.0.1:8080/admin.html`؛ تغییرات Demo در همین مرورگر ذخیره می‌شوند و به Supabase ارسال نمی‌شوند. برای تست Production، لازم است Config واقعی و دسترسی staff معتبر باشد.

**مهم:** اگر پروژه قبلی را در پوشه دیگری اجرا کرده‌ای یا Python server قبلی هنوز فعال است، همان نسخه قدیمی را خواهی دید. سرور قبلی را با Ctrl+C متوقف کن و پوشه جدید را اجرا کن. `dist/` قدیمی را باز نکن. بعد از انتقال به Vercel نیز باید از ZIP جدید Build جدید گرفت.

### تست‌های انجام‌شده
- `npm run qa`: Static، Content، Backend Sync، V7.3 IA/UI checks.
- `npm run build` با publishable key **ساختگی فقط برای Build** و سپس `npm run verify:dist`: موفق؛ کلید ساختگی فقط در خروجی موقت QA استفاده شده و داخل ZIP Source قرار ندارد.
- این محیط اجازه بازکردن صفحات از مرورگر خودکار را نداد. **Browser E2E، تست دستگاه واقعی، URL health و Supabase Production هنوز تأیید نشده‌اند.**

### موارد خارج از دامنه نسخه
- آپلود گروهی فایل و File Manager جامع، بازیابی نسخه‌های قبلی، تاریخچه تغییرات و مدیریت نقش‌ها در UI هنوز پیاده‌سازی نشده‌اند.
- شخصی‌سازی فوتر از داخل پنل بدون Schema/Policy تغییر امن هنوز فعال نیست؛ لینک‌ها از `assets/site-ui.js` قابل تنظیم هستند.
- هیچ محتوای آموزشی جدید، کتاب Core برای B1–C2 یا سرویس خارجی جدیدی ساخته نشده است.

### انتشار امن
قبل از Production از دیتای Supabase بکاپ بگیر، تنظیمات واقعی Auth و Redirect URL را تأیید کن، Cloud Sync و RLS را با نقش Editor/Admin و Guest تست کن، لینک‌های فایل خصوصی و signed URL را بیازما، سپس روی URL Preview Vercel انتشار آزمایشی انجام بده. پس از QA موبایل و دسکتاپ، Production را جایگزین کن.
